## 四、测试中发现的问题和处理

| 问题                                  | 原因                             | 处理                                                    |
| ----------------------------------- | ------------------------------ | ----------------------------------------------------- |
| 回复里出现模型思考内容（`<think>`），还把提示词规则说了出来  | 模型的思考内容混进了回复                   | 确认用 `deepseek-chat`，Dify 把思考内容折叠；回复内容只引用 LLM 的 `text` |
| 回答里说"在售的这几款"                        | 资料里没有在售、库存信息，是模型自己加的           | 提示词加规则：没有价格、库存等信息一律回答无法确认，不使用"在售""有货"                 |
| 说"冰箱有两款"，实际有 4 款                    | 检索只取了 Top K = 3 条，模型把看到的数量当成总数 | 提示词加规则：不说某品类"一共几款"，只介绍资料里出现的商品                        |
| 回复里出现星号                             | Markdown 加粗符号，预览框没有渲染          | 提示词加规则：用纯文本，不使用星号、井号                                  |
| 召回测试时无关商品被召回（空气净化器 0.35、3 匹空调 0.33） | 阈值 0.3 偏低                      | 阈值提到 0.4，其余三条查询结果不变                                   |

## 五、已知限制

- 数据是自建的模拟数据，共 18 个商品，不对应真实产品
- 动作和带看只输出结构化指令（JSON），没有接入真机，没有实际执行
- `target` 只是位置名称，真机需要另外有位置名称到地图坐标的对照
- 知识库没有价格、库存、质保信息，这类问题只能回答无法确认
